# Trailhead

Hiking trail guide for Kananaskis Country. Next.js App Router + Sanity (embedded Studio),
Tailwind + shadcn themed as the "Sketch" paper design system, MapLibre maps, Vercel.

## Start here

1. Read `docs/handoffs/HANDOFF.md`. It says which phase we are in and what to do next.
2. The spec in `docs/spec/` is authoritative. `08-design-system.md` wins over earlier files.
3. Build state lives in `docs/handoffs/`, not in chat. See `docs/handoffs/README.md`.

## Workflow

- Spec review is done by hand (optionally with the `architect` agent) before phase 1.
- Then `/build-phase N` for phases 1 to 6, in order.
- The main session orchestrates. Agents in `.claude/agents/` do the work: architect, researcher,
  implementer, blind-reviewer, qa-runner, scribe.
- Code is written on branch `phase-N` and merged to `main` after a blind review and QA pass.
  Agents never push.

## Rules for anyone touching code

- `src/lib/sanity/types.ts` and `schema.json` are generated by `pnpm typegen`. Never hand-edit.
- No raw hex colours outside `globals.css`, except `src/lib/og-tokens.ts` (OG images can't read
  CSS variables; it mirrors `globals.css` and must stay in sync). No text under 21px under `src/app/(site)/`.
- Every `sanityFetch` passes `tags`. Values used in logic or `href` pass through `stegaClean`.
- `SANITY_API_WRITE_TOKEN` is server-only. Never import the write client from a client component.

## Commands

`pnpm dev`, `pnpm build`, `pnpm typegen`, `pnpm seed`, `pnpm test` (defined in phase 1).
Unit tests only; the rules are under Testing in `docs/spec/00-overview.md`.
